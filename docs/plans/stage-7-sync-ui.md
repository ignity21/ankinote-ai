# Stage 7: AnkiWeb 同步交互方案

状态：已按此设计实现并上线，参见 [后端计划](direct-collection-backend.md) Stage 7
的完成说明。本文档保留作为该功能的交互设计依据。

## 体验目标

用户的主要任务是生成学习卡片。界面应让用户知道卡片是否保存、是否已同步到
AnkiWeb，以及现在是否需要操作。自动同步成功不弹通知；需要处理的问题留在界面中，
提供明确的下一步。

部署可能位于服务器，所以用「ankinote 中的数据」指应用保存的内容，避免将「本地」
误解为浏览器所在的电脑。「已同步到 AnkiWeb」不表示其他设备已经下载完成。

## 视觉与布局

沿用现有蓝色导航和单列设置页。同步区放在设置标题之后，AI 服务配置之前，
使首次初始化和从生成页跳转来的问题处理都能直接找到。

| Token | 色值 | 用途 |
| --- | --- | --- |
| Surface | `#FFFFFF` | 浅色页面背景 |
| Ink | `#0F172A` | 标题和正文 |
| Muted | `#475569` | 时间、辅助说明 |
| Action | `#3D6FA6` | 操作与焦点，沿用应用主色 |
| Attention | `#92400E` | 需要处理的提示，配合图标和文字 |
| Destructive | `#B91C1C` | 覆盖确认、无法继续的错误 |

深色模式沿用现有 `#16181D` 页面与 `#242833` 表面，操作色 `#6FA8DC`；
正文、次要文字和警示色使用相应浅色变体，并检查实际对比度。

字体采用现有界面 sans-serif，中文回退 `PingFang SC`、`Microsoft YaHei`、
`Noto Sans CJK SC`，不引入远程字体。标题 28px/700、分区标题 18px/600、
正文 16px/400、辅助信息 14px/400。正文行高 1.6，内容左对齐。
使用现有 768px 内容宽度，移动端 16px 留白；操作区窄屏换行。

比较过把账号、同步、媒体分别放进三张卡片的布局：这会让一次同步看起来像三个
独立任务。因此采用一个连续的同步区域，以「保存 → 同步」两层结果组织信息，
只在需要选择数据来源时展开较大的交互区。没有统计卡片、装饰渐变或自动入场动画。

正常状态草图（示例时间，不代表当前状态）：

```text
设置

AnkiWeb 同步                            [立即同步]
✓ 已同步到 AnkiWeb
上次完整同步：今天 14:32

账号  learner@example.com                 退出登录
自动同步  每 5 分钟检查一次                  更改
启动应用和保存卡片后，也会自动同步。

────────────────────────────────────────────────
现有 AI 服务设置…
```

同步中使用不确定进度指示和「正在同步…」，不虚构百分比、剩余时间或媒体数量。
保持区域高度和按钮位置稳定。状态更新只更新同步区，不能重建其他设置表单或打断输入。

## 首次使用与账号

- 空资料库：显示「登录 AnkiWeb，完成首次同步后即可保存卡片」和「登录 AnkiWeb」。
  未登录本身不用红色错误。生成页也提前说明初始化要求，避免生成结束才发现无法保存。
- 已初始化但未登录：显示「未登录 AnkiWeb。卡片仍可保存到 ankinote；登录后恢复同步」。
  若仍有全量同步待处理或其他写入阻塞，不显示可保存承诺。
- 登录按钮展开区域内表单：邮箱、密码、密码显示切换，以及「登录并同步」。支持 Enter，
  输入有常驻标签；失败保留邮箱、清除密码，在表单内说明网络或认证问题。
- 登录成功后直接进入同步状态，收起密码表单。认证成功但同步失败，应显示同步问题，
  不能错误提示密码不对。成功、关闭表单后都清除密码，不将密码保存到浏览器持久存储。
- 退出登录旁说明「退出后停止同步，已保存的卡片保留」。这是明确的账号操作，不加重复
  确认弹窗。已经绑定的资料库不能通过退出后登录另一个账号来换绑；说明需要单独配置资料库。
- 环境配置账号显示「账号由部署配置管理」，隐藏 UI 登录和退出操作；认证失败时指向更新
  部署配置并重启，不提供必然失败的登录按钮。仅展示服务端明确允许公开的账号标识。
- 自动同步默认 5 分钟；「更改」展开正整数分钟输入和「保存同步间隔」。成功时就地显示
  「已保存」，失败保留输入。不依赖页面底部的 AI 设置保存按钮，也不暗示间隔控制保存后同步。

## 状态与下一步

渲染须结合 `initialized`、`full_sync_required`、`error` 和最近结果，不能仅按状态枚举
决定是否允许保存。阻塞写入的原因优先呈现；重新登录仍是认证失效后的必要第一步。

| 情况 | 用户看到的内容 | 操作 |
| --- | --- | --- |
| 首次同步中 | 正在准备 Anki 资料库，完成后即可保存卡片 | 等待；不重复提交 |
| 正常空闲 | 已同步到 AnkiWeb；上次完整同步时间 | 立即同步 |
| 同步进行中 | 正在同步…；保留上次完整同步时间 | 同步按钮禁用并显示忙碌状态 |
| 网络失败，已初始化且无阻塞 | 暂时无法连接 AnkiWeb，已保存的卡片保留，将自动重试 | 查看详情；真实支持立即重试后才提供该操作 |
| 网络失败，尚未初始化 | 首次同步尚未完成，连接恢复后将自动重试；暂时无法保存卡片 | 查看详情 |
| 卡片同步成功、媒体失败 | 卡片数据已同步，图片或音频尚未同步完成 | 网络原因自动重试；其他媒体错误提供重试同步 |
| 认证失效 | 登录已失效，请重新登录以恢复同步 | 重新登录，或部署配置说明 |
| 需要全量同步 | 需要选择使用哪一份数据，处理前暂时无法保存新卡片 | 选择数据来源 |
| 同步或状态保存错误 | 无法完成同步；有写入阻塞时明确说明 | 安全的重试入口或具体配置处理说明 |

`last_success` 只标注「上次完整同步」，没有值时显示「尚未完成首次同步」。历史成功
不能盖过当前错误。最近结果与当前状态分开，媒体失败不能显示整体「已同步」。
错误详情只使用受控文案，不直接输出可能含凭据的异常。

## 全量同步：选择数据来源

需要选择时展开设置页中的固定提示，不自动弹出模态框。生成页用持久提示链接到这里。
选择页说明：「两边的数据需要通过一次完整上传或下载来同步。请选择要保留哪一份。」

```text
需要选择使用哪一份数据
处理前暂时无法保存新卡片。

( ) 使用 AnkiWeb 的数据
    下载并替换 ankinote 中的卡片和学习记录。

( ) 使用 ankinote 的数据
    上传并替换 AnkiWeb 上的卡片和学习记录。

                                             [继续]
```

- 两项均不默认选中，也不自动推荐方向。只允许后端确认可用的方向；不可用时给出原因。
- 选中后「继续」打开一次覆盖确认，明确来源、目的地和影响。最终按钮为「下载并替换」
  或「上传并替换」，另一操作为「返回」。不使用含糊的「确定」。
- 确认中说明会先备份 ankinote 资料库，备份失败就停止；不声称该备份能恢复 AnkiWeb
  被覆盖的数据，也不把资料库备份描述成媒体的完整备份。
- 执行前重新检查状态和可用方向。执行时禁用重复提交；不显示后端尚不支持的取消按钮。
- 用户可以离开设置页，应用继续处理。若未确认，写入仍保持暂停，提示不会因为关闭而消失。
- 若备份失败，明确显示「无法创建备份，尚未开始替换」，保留处理入口。

## 生成卡片时的反馈

Word、Phrase、Sentence、STEM 使用一致的规则。每张卡片的结果只报告其保存结果，
整批任务下方独立报告 AnkiWeb 同步，避免每张卡片弹一次同步通知。

```text
✓ 已保存 8 张卡片到 ankinote
  图片或音频尚未同步完成。连接恢复后将自动重试。  查看同步状态
```

只有网络类失败才承诺自动重试；认证失败改为「请重新登录以同步图片和音频」。
保存成功保持成功标记。重试同步不能重新生成或重复添加卡片。
如果批量保存部分失败，保留保存成功数和失败项，另行显示同步结果。

首次初始化或全量同步待处理时，在生成操作前显示阻塞原因和设置入口，保留现有输入与
预览。后台状态可能在生成中改变，最终保存被拒绝时仍须保留生成结果并提示处理后重试保存。
后端继续作为写入权限的最终判断方。

AnkiConnect 模式显示「通过 Anki 桌面端连接」及「请在 Anki 中同步到 AnkiWeb」，
不提供无效的 AnkiWeb 登录表单。笔记类型页面使用「更新笔记类型」及
“Update note types”，云端操作使用「同步到 AnkiWeb」及 “Sync to AnkiWeb”。

## 实现前需要补齐的接口

目前后端有状态快照和登录/退出/同步操作，但以下体验不能只靠页面包装完成：

- 提供公开且不含凭据的账号展示、写入阻塞原因、可用全量同步方向和受控错误原因。
  当前驱动的通用 `driver` 错误不足以区分备份失败与方向不可用，不能靠 UI 猜测。
- 提供同步间隔持久化和运行时更新入口。目前间隔只在服务初始化时传入。
- 当前网络退避期间 `request()` 返回现状；如果呈现「立即重试」，需提供安全地跳过退避、
  合并并发请求的服务入口，否则界面只能如实显示等待自动重试。
- 保存结果与后续同步结果需要分别传给页面，才能在保存完成时及时显示成功；不能通过
  捕获所有异常推断保存已完成。保留生成结果以便只重试保存也需要明确的页面任务状态。
- UI 订阅或轻量轮询同一运行时状态，离开页面时清理订阅；不能在页面中另开资料库。

## 验收

- 七种同步状态及未初始化、认证失效、媒体失败、全量同步待处理的组合都有渲染测试。
- 全量同步没有默认方向；返回不执行；双击不重复执行；备份失败不开始替换。
- 保存成功加媒体失败仍显示保存成功，重试只调用同步；批量部分失败结果不丢失。
- 输入过程中刷新状态不丢失焦点、密码输入或其他设置草稿；同步结束不弹抢焦点的对话框。
- 手机宽度、深色模式、中英文长文案均可用。所有按钮支持键盘与可见焦点；状态使用
  `aria-live="polite"`，只播报实际变化，状态含文字而非只靠颜色，减少动态效果设置受尊重。
- UI 测试使用假服务；不登录个人 AnkiWeb 账号。实施后运行仓库要求的 lint、check、test，
  并对首次使用、正常、媒体失败和全量同步选择状态截图复核。
